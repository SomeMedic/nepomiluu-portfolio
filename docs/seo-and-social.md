# Метаданные и социальные обложки

## Публичные страницы

Главная RU/EN и каждый опубликованный кейс получают самостоятельные `title`, `description`, canonical, взаимные `hreflang` для `ru`, `en` и `x-default`. Русская версия — языковой fallback; canonical каждой страницы указывает на неё саму. HTML и sitemap используют один генератор URL. Метки кампаний и переданный клиентом `Host` не меняют canonical.

Все абсолютные адреса строятся из проверенного runtime `SITE_URL` / `PUBLIC_ORIGIN`. В production требуется HTTPS. На этапе Docker-сборки API и база не нужны.

Open Graph содержит название, описание, тип, URL, имя сайта, локаль, другую локаль, изображение, MIME и alt. Для подготовленных JPEG указаны реальные 1200 × 630. Twitter Card использует `summary_large_image`, согласованные тексты и тот же файл с alt. Ульяне не приписывается неподтверждённый X-аккаунт.

`htmlLimitedBots: /.*/` сохраняет метаданные в первоначальном `<head>` для всех клиентов, включая Telegram, которого нет в стандартном списке текущего Next. Генерация метаданных кейса использует тот же кешированный запрос опубликованного контента, что и страница; отдельного запроса к CMS для картинки нет. Подробности поведения: [Next.js htmlLimitedBots](https://nextjs.org/docs/app/api-reference/config/next-config-js/htmlLimitedBots).

| Клиника Фомина | `/social/fomina-cover-v1.jpg` | 1200 × 630 | 84618 байт |

Домашние обложки — специально созданные редакционные композиции: крупная антиква, курсивная строка, молочная бумага, тонкая терракотовая кривая. Это отдельная обложка для ссылки, а не уменьшенный скриншот интерфейса. Встроенный imagegen применён в режимах генерации и локализации текста; исходники и инструкции находятся в `assets/originals/social/`. Портрет не генерировался и не менялся.

Обложки кейсов изготовлены из предоставленных пользователем презентаций, без обрезки содержимого: полный кадр вписан в формат с молочными боковыми полями. Их выбор привязан к `mediaId` обложки, а не к slug проекта. Если владелец меняет обложку через CMS, метаданные используют выбранное опубликованное медиа. Для такого файла не выдумываются неизвестные размеры. Если обложки нет, используется локализованная карточка портфолио.

Версия в имени файла позволяет выпускать новую картинку по новому URL. Параметры экспорта и SHA-256: [social-assets-manifest.json](social-assets-manifest.json). Подготовка и независимая проверка:

```powershell
node scripts/prepare-social-assets.mjs
node scripts/prepare-social-assets.mjs --check
```

Скрипт использует уже установленный Sharp API-приложения; новых зависимостей нет. Помимо JPEG он создаёт PNG-иконки 32/48/180 и ICO из исходного `src/app/icon.svg`. SVG — развитие существующего словесного знака `uliana.` в монограмму `u.`, без внешних шрифтов или сетевых запросов. Сам SVG подключает файловый Metadata API Next, без дублирующего маршрута в `public`.

## Структурированные данные

В серверном HTML главной размещён граф `Person` + `WebSite` + `ProfilePage`. Публичные кейсы описаны как `WebPage` + `CreativeWork` со ссылкой на того же автора. Имя, профессия, Telegram и VK соответствуют видимому содержимому. Не добавлены адрес, рейтинги, награды, число клиентов или другие неподтверждённые сведения.

В публичном API `publishedAt` — время последней публикации снимка. Оно используется как `dateModified` / `article:modified_time`; дата первой публикации не подменяется последней. JSON-LD экранирует `<`, поэтому текст из CMS не может закрыть `<script>`.

Разметка помогает описать автора и работы; появление расширенного результата в поиске не гарантируется. Источники правил: [Open Graph](https://ogp.me/), [Google о языковых версиях](https://developers.google.com/search/docs/specialty/international/localized-versions), [ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page), [CreativeWork](https://schema.org/CreativeWork).

## Индексация и приватность

- В sitemap попадают главные RU/EN и только опубликованные кейсы; `lastmod` берётся из реальной публикации.
- Админка и авторизованные preview сохраняют `noindex, nofollow, noarchive`.
- Локальный `ALLOW_STATIC_CONTENT=true` запрещает индексацию главной, кейсов и всего демонстрационного сайта в robots.txt.
- Роботам разрешён `/api/media/`, чтобы загруженные публичные обложки были доступны. Контроль публикации и авторизации в API сохраняется; robots.txt не выдаёт доступ к приватным файлам.
- Search Console, внешние счётчики и новые сервисы не подключаются.

## Проверка

`seo.test.ts` проверяет контракты языковых URL, смену CMS-обложки, отсутствие выдуманной даты первой публикации, preview noindex и защиту границы JSON-LD. `metadata.spec.ts` проверяет реальный первоначальный HTML для Telegram, VK, Twitter, Facebook и обычного клиента, страницы без JavaScript, картинки, иконки, sitemap, robots, админку и 404 локали. В CI также проверяются хеши и декодированные размеры изображений.

После публикации выполняется проверка самого HTTPS-сайта:

```powershell
node scripts/check-social-metadata.mjs https://nepomiluu.art --output=output/verification/social-metadata/production.json
```

Она проверяет все адреса опубликованных кейсов, метаданные в `<head>`, canonical/языковые связи, JSON-LD, MIME, размеры и SHA-256 подготовленных картинок, иконки, robots и sitemap. Это проверка доступности для бота, а не подтверждение обновления внешних кешей Telegram/VK/X. Уже отправленная ссылка может некоторое время показывать старое превью, пока соответствующая платформа не перечитает страницу. Тестовые сообщения от имени пользователя не отправляются.
