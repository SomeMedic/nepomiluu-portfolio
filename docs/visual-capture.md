# Воспроизводимый захват главной

`scripts/visual-capture.mjs` открывает уже работающий `http://127.0.0.1:3000/ru` или `/en` в отдельном headless Chromium. Скрипт не запускает и не останавливает сервисы, не читает `.env`, не выполняет CMS-запросы и не меняет DOM, стили или анимации приложения. Нужны установленные зависимости проекта и Node.js 24.

```powershell
node scripts/visual-capture.mjs --section all --width 1586 --height 992 --locale ru --motion reduce --out output/playwright/home-ru-reduce
node scripts/visual-capture.mjs --section process --width 1586 --height 992 --locale ru --motion normal --out output/playwright/process-ru-normal
```

Если глобальный Node другой версии, используйте локальный portable runtime:

```powershell
& .\.tools\node-v24.22.0-win-x64\node.exe scripts/visual-capture.mjs --section all --width 1586 --height 992 --locale ru --motion normal --out output/playwright/home-ru-normal
```

Параметры:

| Параметр | Значения / значение по умолчанию |
| --- | --- |
| `--section` | `hero`, `clypse`, `fomina`, `logic`, `experience`, `process`, `footer`, `all`; по умолчанию `all` |
| `--width`, `--height` | Целые CSS-пиксели, 240–7680; по умолчанию `1586 × 992` |
| `--locale` | `ru` или `en`; по умолчанию `ru` |
| `--motion` | `reduce` или `normal`; по умолчанию `reduce` |
| `--out` | Каталог результатов; по умолчанию новый `output/playwright/visual-capture-<timestamp>` |
| `--help` | Справка без запуска браузера |

Используется тот же выбор браузера, что в E2E: `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, затем установленный Chrome/Edge на Windows, затем Chromium Playwright. Указанный явно путь должен существовать. Скрипт ничего не скачивает. Для сравнения результатов сохраняйте одну версию браузера, ОС, контент CMS, viewport, язык и режим motion. Состояние контента и фактические URL изображений видны в JSON.

Каждая секция открывается в новом контексте без cookies и сохранённой прокрутки. После загрузки шрифтов и начальной анимации скрипт позиционирует страницу, ждёт видимые изображения и стабильные геометрию/opacity/transform. `hero` снимается при `scrollY = 0`. В `normal` для Clypse и процесса выполняется настоящий клик по ссылке `#clypse-stage-1` / `#process-stage-1` — это второй этап, индекс `1`; позицию вычисляет существующий обработчик приложения. Для закреплённой «Логики» выбирается 85% pin-интервала: третий этап с полностью раскрытой композицией. Остальные секции и статический `reduce` начинаются с верхней границы секции. У короткого футера браузер ограничивает прокрутку концом документа. На малых размерах приложение может выбрать обычный поток вместо закрепления: фактическое состояние записывается в метрики.

PNG содержит **ровно один viewport** с `deviceScaleFactor = 1`, без full-page сшивки и масштабирования. Высокая статическая секция в `reduce` обрезается нижней границей viewport, её содержимое не сжимается. Для полного чтения длинных секций используйте браузер; этот инструмент фиксирует заданные контрольные кадры.

Если после двух обычных кликов fragment URL не изменился, скрипт использует стандартный `window.scrollTo` до измеренной середины pin-интервала (или до второго этапа в обычном потоке). Это явно отмечается в `position.scrollFallback` и предупреждениях: кадр фиксирует нужный этап, но не подтверждает исправность навигации. Hash, классы, GSAP-состояние и стили скрипт не подменяет. После перестройки pin-блоков из-за lazy-изображений положение обычных секций измеряется повторно.

В каталоге сохраняются:

- `<section>.png` — кадр с проверенными размерами PNG;
- `<section>.json` — фактическая прокрутка, размеры секции/заголовков/этапов/ссылок/изображений, состояние pin и активного этапа, шрифты, типографика, цвета, горизонтальное переполнение, ошибки и предупреждения;
- `report.json` — параметры, версия/путь браузера, результаты всех секций, ошибки JS, console, сетевых запросов и HTTP ≥ 400. При неудачном захвате причина остаётся здесь и, когда DOM доступен, в `<section>.json`; остальные секции продолжают сниматься.

Повторный запуск в тот же `--out` перезаписывает одноимённые файлы. Код завершения `0` означает, что все запрошенные кадры получены без зарегистрированных ошибок; `1` — ошибку аргументов, браузера, загрузки или захвата. Предупреждения о переполнении, ограничении прокрутки и нестабильной анимации требуют просмотра отчёта, но сами не меняют код завершения. Это сбор доказательств для визуальной проверки: он не утверждает соответствие макету и не заменяет визуальный просмотр.
